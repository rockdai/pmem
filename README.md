# Personal Memory

Personal Memory 是一款开源、支持用户自托管的个人知识库产品。

我们的长期愿景是帮助用户积累和使用自己的知识。近期先做好一款用户体验好的个人在线记事本，让用户在想法出现时，能够迅速开始记录，并在不同设备上继续使用。

## 当前产品目标

围绕「打开 → 记录 → 保存 → 再次访问」做好最基本的体验。现阶段的功能和技术选择，优先服务于这条使用路径。

人们的思绪和灵感稍纵即逝。打开速度直接决定一个想法能否被及时记录，因此它是产品的核心要求。

## 一期范围与技术约束

- 一期完成服务端和 Web 端的开发。
- 服务端采用 Node.js，沿用熟悉的技术栈。
- Web 端承担一期的多端使用入口，并满足打开快、方便记录的要求。
- 每个部署一个个人账号，支持本人在多台设备使用。
- 一期聚焦 MVP：登录、最近修改笔记列表、新建、富文本编辑、自动保存、删除和多设备访问。
- 服务端只使用本地文件或 OSS 中的一种存储，正文直接保存为文档文件，不使用 JSON 封装。
- 数据文件只保存笔记内容及必要的内容格式，界面 HTML、CSS、主题和编辑器 UI 状态由 Web 端负责。
- 一期不做搜索、索引、备份和历史版本；每篇笔记只保留当前内容，后续历史功能仅预留扩展位置。

## Web 编辑器体验

- 编辑器体验参考 Notion，具体功能范围根据个人记事本的需求确定。
- 优先考虑富文本编辑，让用户能够方便地组织和表达内容。
- 「打开快」是编辑器选型和功能范围的硬约束。富文本方案需要满足打开速度要求；发生冲突时，优先保证用户能快速开始记录。
- 选型时应将编辑器的加载和初始化纳入「打开到可输入」的完整耗时，依据实测结果确定方案。

## 两项硬指标

### 打开快

- 以用户从打开产品到能够输入第一个字的耗时衡量打开速度。
- 页面显示、加载动画结束都不能单独代表打开完成；编辑区域必须真正能够接收并保留输入。
- 验收应覆盖首次访问、日常再次打开和后台恢复，并明确对应的设备、网络及缓存条件。

### 支持多端

- 用户能够在不同设备上访问和记录自己的笔记。
- 多端体验既要考察内容能否衔接，也要考察各端能否方便、快速地输入。
- 各端均需满足打开速度要求。

## 开源与自托管

开源和用户自托管是产品的基本定位。部署方式和外部服务依赖的选择，需要兼顾用户自行运行产品的能力。

## 后续需要明确的验收标准

以下事项尚未确定，应在技术选型和实现方案中明确：

- Web 端首批支持的设备、浏览器及版本范围。
- 各类打开场景的耗时门槛、统计口径及测试环境。
- 一期富文本编辑的功能范围，以及候选编辑器的实际打开性能。
- 跨端内容同步的时效、保存状态反馈及同时编辑时的处理方式。
- 弱网、断网时的记录与恢复行为。

后续方案应说明其对打开速度和多端体验的影响，并通过实际使用路径验证这两项要求。
