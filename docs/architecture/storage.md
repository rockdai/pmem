# MVP 文件存储设计

状态：设计提案，尚未实现。更新日期：2026-09-23。

## 1. 范围

一期只使用本地文件或阿里云 OSS 中的一种存储。每篇笔记只有当前内容，不做搜索、索引、备份、历史副本或归档。

浏览器 IndexedDB 只保存当前草稿与待提交状态，不增加服务端数据库依赖。应用运行在一个活动 Node.js 实例中，所有设备经该实例读写。

## 2. 正文格式

推荐直接保存 UTF-8 Markdown 文件：内容是用户写下的文字，以及标题、列表、加粗等内容格式的 Markdown 标记。界面样式、主题和编辑器 UI 状态由 Web 端负责。Markdown 是本提案的推荐格式，用户已明确的要求是只保存笔记内容，不存页面 HTML 和样式。

```text
notes/
  <note-id>.md
```

文件只包含笔记内容，不加 HTML 页面、CSS、JSON 外壳、front matter 或隐藏的提交标记。标题从首个非空内容行派生，完整内容一起保存。文件名由稳定 ID 决定，修改内容或标题不改路径。

列表仅读取文件的有界开头片段（建议最多 8 KiB）提取标题；显示时可去掉 Markdown 标记并截断，但不改写原文。片段内没有可用内容时显示“未命名笔记”。正文原型先以 1 MiB 测试边界，不为列表读取整篇正文。

编辑器显示为可视化富文本，保存时转换成 Markdown，打开时从 Markdown 恢复；用户不必手写标记。Tiptap 官方 Markdown 扩展当前为 Beta，需验证其具体版本与一期功能的兼容性。编辑器运行时的内部模型不写入文件，Markdown 解析与转换的开销仍须计入启动预算。[Tiptap Markdown 文档](https://tiptap.dev/docs/editor/markdown)。

一期仅提供约定 Markdown 能表达的编辑功能，任务列表使用常见的任务项扩展语法。验证标题、列表、强调、任务状态、链接、代码块、中文和换行的往返；连续空段落等未必能被标准 Markdown 无损表达的结构须明确约定编辑行为，不能默认支持所有富文本结构。遇到不支持的内容保留原文和草稿，不能静默丢失。

服务端按文件字节读写，不为了存储把正文转成 JSON 或 HTML。通过认证接口以 `text/markdown; charset=utf-8` 返回，并禁止 MIME 嗅探；内容摘要通过响应头返回。渲染时不执行原始 HTML 或危险链接，代码块中的标记保持文本含义。

## 3. 无索引的笔记列表

本地模式直接列举 `notes/` 的文件名，OSS 模式通过 ListObjectsV2 分页列举相同前缀的对象。仅为当前页读取内容开头片段取得标题；限制并发，完整正文在用户打开时再读取。

列表采用稳定 Key 顺序，暂不提供依赖全库扫描的“按最近编辑时间排序”。本地可以排序文件名后分页，OSS 使用列举游标；并发新增或删除后允许刷新列表，不维护目录清单文件或搜索索引。

列表加载不阻塞编辑器可输入。服务启动不扫描全部正文。OSS 列表需要额外读取当前页内容片段，这部分请求成本纳入验收。[OSS ListObjectsV2](https://www.alibabacloud.com/help/en/oss/developer-reference/listobjectsv2)。

## 4. 当前文件提交

存储层只暴露列举、读取、创建、替换和删除。应用层按 noteId 串行执行修改，对实际保存的 UTF-8 字节计算 SHA-256 作为当前内容校验标识；不把摘要写入笔记内容。HTTP API 可以使用 If-Match，但这是应用负责校验的协议，不直接假设 OSS 支持条件覆盖。

- 新建与更新是不同操作；更新目标不存在时返回明确错误，不能自动重建已删除的笔记。
- 替换前检查客户端读取时的校验标识，冲突时保留客户端草稿，由用户处理。
- 每次提交固定目标内容及其摘要，操作标识只出现在协议或部署侧待确认状态中。相同内容无需重复写入；当前文件匹配目标摘要时可以确认目标内容已保存，不据此声称拥有历史操作记录。
- 若当前文件已被其他提交替换，无法靠当前文件证明更早请求的全部历史。此时重新核对并报告冲突，不承诺跨任意时间的历史幂等结果。
- 同一笔记前一次请求未确认时，不发送后继内容；请求中途的新输入留在浏览器当前草稿。

这些提交信息与用户内容分离，不保存旧正文，也不建立版本目录。

### 本地文件

同一文件系统内写入临时文件并同步，完成后原子替换当前文件，再同步父目录；新建使用不覆盖已存在目标的发布方式。异常时不能暴露半写文件或提前返回成功。临时文件是未完成写入，不作为历史副本保留。

发布前的校验与替换由同一应用实例中的笔记写入队列保护。只支持经过验证的本地文件系统，部署时不允许两个实例共同修改数据目录。[Node.js 文件操作](https://nodejs.org/docs/latest-v24.x/api/fs.html)。

### OSS

直接读取和覆盖 `notes/<note-id>.md`。OSS 的单对象操作具有原子性和强一致性，但普通 PutObject 不支持 If-Match 条件覆盖；并发检查由唯一 Node.js 写入入口和每篇笔记的串行队列完成。[OSS 一致性](https://www.alibabacloud.com/help/en/oss/user-guide/what-is-oss)、[OSS 条件上传限制](https://help.aliyun.com/zh/oss/user-guide/0017-00000245)。

正常写入完成后返回保存成功。写入超时必须进入“结果待确认”：保留浏览器草稿和部署侧最小待确认记录，暂停同一笔记的后续修改，读回完整文件计算摘要，与目标摘要核对。记录包含请求标识、原摘要和目标摘要，不保存旧正文，也不插入 Markdown 文件。

修改请求关闭 SDK 和代理的自动重放，避免迟到的旧请求覆盖新内容。读回本次提交可以确认成功；读到旧内容不等于旧请求已经终止，不能据此立即放行后继写入。重启后仍要处理未确认请求，不能丢弃状态后继续覆盖。无法确认结果时保持阻塞并明确反馈，不虚报失败或成功；这是 OSS 适配需要真实故障测试的边界。

Bucket/前缀由应用独占写入，一期不启用应用管理的对象版本功能；所选部署配置应避免自动生成历史对象。此方案不依赖禁止覆盖请求头构造版本日志，也不把对象存储当作支持多对象事务的数据库。

## 5. 后续扩展预留

笔记 ID 保持稳定，文件读写集中在存储适配器中。以后增加历史功能时，可以新增独立历史目录或对象前缀，将每次历史内容保存为独立文件。

MVP 不创建该目录，不复制旧内容，不加入历史记录、恢复或备份流程。当前只验证单篇当前内容的正确读写和多端冲突提示。
