# MVP 性能与多端验收

状态：验收目标；已取得的实测与未验证环境见 [实现验证记录](../validation/task-090.md)。更新日期：2026-09-23。

## 1. 验收口径

主指标 T_ready 是从导航开始，到正确内容已准备好、编辑器能接受输入、本地草稿保存链路可用的时间。必须实际输入字符并验证落盘及重开恢复，不能只看页面显示、焦点或 contenteditable 属性。

普通导航从 Navigation Timing 起点计时；应用内新建和切换从用户操作计时；驻留页面恢复从恢复可见计时。手机另外记录点击编辑区到键盘可用的体验，以及系统入口到可记录的端到端时间。

文件读取、Markdown 解析、编辑器初始化和本地持久化分别打点，报告完整链路。正文采用推荐的 Markdown 方案验证，不以取消 JSON 封装推断性能已经提升；数据文件不包含界面 HTML、CSS 或编辑器 UI 状态。

## 2. 建议目标

在固定参考设备与标准网络下，按场景、平台分别统计 P95：

| 场景 | 桌面 | 手机 | 条件 |
| --- | --- | --- | --- |
| 首次打开编辑路由 | ≤ 1.5 s | ≤ 2.5 s | 资源和内容缓存为空，会话已建立 |
| 日常重新打开 | ≤ 500 ms | ≤ 800 ms | 资源及目标内容已缓存，标准网络 |
| 驻留页面回到前台 | ≤ 200 ms | ≤ 300 ms | 编辑实例未被系统回收 |
| 应用内新建或切换缓存笔记 | ≤ 200 ms | ≤ 300 ms | 普通规模笔记 |
| 内容变化到本地保存完成 | ≤ 100 ms | ≤ 200 ms | 持续输入及中文组合输入分别测 |

首次登录的人工输入时间单独扣除，登录成功到可输入目标为桌面 1 s、手机 1.5 s。未缓存笔记必须计入正文读取；不能展示空白内容并算作已打开原笔记。

停止输入到服务端保存确认建议 P95 ≤ 1.5 s，包含保存防抖；其他前台设备通过 5 s 条件轮询，建议在确认后 7 s 内发现变化。冲突时展示提示，不覆盖正在输入的内容。后台不承诺持续同步。

首字输入所需 JavaScript 初始预算为合计 250 KiB gzip，CSS 为 30 KiB gzip。所有输入前必须加载的动态 chunk 都计入，不通过拆包改变统计口径。

Markdown 解析与转换、路由、Dexie 或替代的 IndexedDB 封装也计入预算；保存时的 Markdown 序列化与浏览器草稿写入分别测量，避免转换导致连续输入卡顿。React、Tiptap、Dexie 等为候选而非无条件固定选型，预算不达标时按实现规格 §8 调整依赖并重测，不能降低持久化要求。

## 3. 参考环境

| 维度 | 建议配置 |
| --- | --- |
| 服务端 | 2 vCPU、2 GiB 内存 Linux；分别测试本地 SSD 和 OSS |
| 浏览器 | 桌面 Chrome、Edge、Firefox、Safari；Android Chrome、iOS Safari |
| 设备 | 固定日常笔记本、中端 Android、仍在支持范围的较旧 iPhone |
| 标准网络 | 下行 10 Mbps、上行 2 Mbps、RTT 150 ms |
| 弱网 | 下行 1 Mbps、上行 256 Kbps、RTT 300 ms、1% 丢包；已打开页面断网 |
| 数据 | 空库、1,000 篇、10,000 篇；普通 2,000 字、20,000 字长文及接近 1 MiB Markdown |

记录确切设备、系统、浏览器、SDK、地域、构建版本和网络设置。每个主要场景至少 30 次，保留原始数据、P50、P95、最大值和失败次数。手机视口模拟不能替代真机输入测试。

本地与 OSS 分别报告打开、保存和列表首屏时间。最近修改列表测量包含全库元数据列举/排序、当前页内容开头片段请求、总请求数和字节数；10,000 篇时验证第一页确实包含最近编辑的笔记，并检查时间相同时 ID 排序及游标分页。不能用本地成绩代表 OSS。使用生产构建及真实缓存头，不用开发服务器成绩作结论。

一期列表延迟仅报告、不设通过门槛，覆盖 1,000 和 10,000 篇；此决定明确接受无索引的 O(N) 扫描成本。列表不阻塞新建及已有本机内容的编辑就绪，但新设备找回笔记仍受列表速度影响，报告必须单独披露，不能把 T_ready 成绩作为列表速度成绩。

另测 OSS 条件轮询成本：单个未编辑的 1 MiB 笔记，在缓存已热、无其他操作的情况下主动执行 12 次间隔 5 s 的条件检查，预期 12 次 HEAD、0 次完整 GET、0 正文字节。重启或淘汰后的第一轮允许完整 GET 一次，随后恢复热缓存行为；对象变化、写入缓存失效和 HEAD 故障分别验证。报告 HEAD 与 GET 次数及字节数，不将 HEAD 视为免费操作，也不以缓存命中跳过待确认写入核对。

## 4. MVP 必过用例

| 用例 | 预期 |
| --- | --- |
| Markdown 保存再打开 | 支持范围内的标题、列表、强调、任务状态、链接、代码块和中文语义保持一致；换行与空段落遵守已明确的格式约定 |
| 检查笔记数据文件 | 只有内容及 Markdown 标记，不含页面 HTML、CSS、主题、隐藏元数据或编辑器 UI 状态 |
| 中文输入、粘贴、撤销、手机键盘 | 内容、选区和焦点正确，键盘不遮挡当前输入 |
| 新建后未输入、仅空段落、开始输入后清空 | 未发 POST 的空笔记不落远端；有内容才创建；在途创建和已存在笔记清空遵守创建确认与更新协议 |
| 浏览器确认保存后刷新或普通进程重启 | 当前草稿可恢复；清除浏览器存储不在保证内 |
| 草稿槽位生命周期 | 复制标签不覆盖原槽位；无新输入且已同步记录及时回收；崩溃未同步草稿保留；超过 5 份可分页恢复，不因超时或数量丢弃 |
| 远端保存期间继续输入 | 旧响应不覆盖新内容，也不把新内容标成已同步 |
| 同一笔记多设备或多标签页编辑 | 检测旧内容提交，保留草稿并提示处理 |
| 其他设备删除后提交旧编辑 | 不自动重建已删除笔记 |
| 断网、会话过期、本地写入失败 | 状态准确，当前内容保留并可复制 |
| 2 MiB 粘贴、服务端 413 / 400、随后刷新 | 不截断正文，不陷入远端提交循环；本机存储失败时不虚报保存；缩减至上限内或明确修正请求后才恢复 |
| 保持会话密钥不变，仅修改密码哈希并重启 | 旧 Cookie 读取、写入和会话检查均返回 401，新密码登录成功；未变配置下正常重启仍遵守原会话有效期 |
| 本地替换中断或磁盘满 | 不暴露半写文件，不返回虚假成功 |
| OSS 写入响应丢失或超时 | 读回内容并核对目标摘要；结果不明时阻止后继覆盖 |
| 服务在 OSS 写入待确认时重启 | 恢复待确认状态，不因队列丢失而继续覆盖 |
| OSS 状态卷丢失、错挂、tmpfs、容器遗漏挂载 | 启动拒绝，不重建空状态或向 notes/ 发出修改；正常持久卷重启可恢复；首次初始化在各中断点重试不替换已有身份 |
| OSS 校验缓存冷/热/淘汰/对象变更 | SHA-256 不与 OSS 原生 ETag 混用；热轮询不读正文，冷读取重建；HEAD 失败不返回假 304，待确认核对绕过缓存 |
| 当前文件已被后续提交替换后重试旧提交 | 重新核对或提示冲突，不回写旧内容 |
| 最近修改列表、新设备访问及并发增删改 | 新设备可找到刚保存笔记，同一设备可恢复最后打开笔记；分页允许非快照并按 ID 去重，刷新后正确；列表请求不阻塞新建和输入 |
| 修改现有笔记多次 | 存储仍只有当前正文，不产生应用历史文件或索引文件 |

验证记录包含代码提交、依赖锁文件、构建资源清单、测试配置、原始结果及手机记录。未取得的环境须明确标记；搜索、索引、备份和多版本不属于本轮实现或验收范围。
